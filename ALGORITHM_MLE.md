# Chain-restricted ANI by maximum likelihood (`syn2bani ani`)

Status: implemented 2026-07-25. Additive — `dist`, `sketch`, `db`, `search`,
`struct` are untouched and still use the GBRT path.

This document explains why the calibration approach was replaced rather than
extended, what the new estimator is, and what has and has not been validated.

---

## 1. The problem with calibrating `raw_ani` + `mash_ani`

The GBRT models (v2 → v7) treat `raw_ani` and `mash_ani` as two features and
learn a correction. That framing is the root cause of the degeneracy, not a
tuning problem, for three separate reasons.

### 1.1 `raw_ani` is pinned by the mismatch budget

`local_ani = 1 - hamming / tag_len` with `near_match_tolerance = 2` can only
take the values `{1.0, 0.969, 0.938}` on a 32 bp tag. Its mean is therefore
bounded below by `1 - 2/32 = 0.9375` no matter how divergent the genomes are.

Measured slope of `raw_ani` against known truth over 85–99.9% ANI: **0.336**.
The signal is compressed roughly 3×, so inverting it amplifies noise 3×. GBRT
v7 assigns this feature the highest importance (0.3197).

### 1.2 Genome-wide containment conflates divergence with shared content

With tag length `k`, observed genome-wide containment is

```
C_genome  ≈  (1 - F) · ANI^k          F = accessory / non-homologous fraction
```

so `C^(1/k)` returns `ANI · (1-F)^(1/k)`, biased by an amount that depends on
`F` — which varies from pair to pair. A constant additive offset on
`1 + ln(C)/k` is algebraically identical to hard-coding one fixed `F` for every
comparison. It appears to work on a validation set whose pairs happen to share
similar content, and fails as soon as they do not. That is exactly what the
`-0.028` empirical offset is doing.

### 1.3 Mixing enzymes with a single `k` is biased

`tag_length` ranges from 25 (BslFI) to 33 (CspCI) in the panel. At 98% ANI the
exact-match retention spans 0.51–0.60 across those enzymes. Pooling them and
inverting with `k = 32` shifts the estimate by ~0.18 percentage points at 98%
and ~0.04 at 99.5% — small in absolute terms, decisive at strain resolution,
and it **drifts when the enzyme panel changes**.

### 1.4 The actual relationship

`raw_ani` and `mash_ani` are not independent features. They are two moments of
one likelihood: the mismatch histogram and the loss rate are both generated by
the same per-base divergence. Fitting that likelihood removes the need for a
learned combination and removes the degeneracy — when the histogram saturates,
the fit falls back on the loss rate automatically, weighted by Fisher
information rather than by training data.

## 2. The estimator

### 2.1 Model

A Type IIB tag contains its own recognition site, so a query tag exists only if
that site survived in the query. For a query tag inside a homologous region,
with `k` = tag length, `s` = recognition-site length, `b = k - s` = mutable
body, and mismatch budget `tol`:

```
found with m body mismatches   P_m(a) = C(b, m) · (1-a)^m · a^(k-m)     m ≤ tol
not found                      P_miss(a) = 1 - Σ_{m≤tol} P_m(a)
```

Mismatches are only observable in the body: a mutation in the site deletes the
tag from that genome entirely. The site therefore contributes `a^s` (folded into
`a^(k-m)`) but never appears as an observed mismatch. This also sets a hard
ceiling on retention — no mismatch budget can recover more than `a^s` of the
tags, which is ~0.72 at 95% ANI and ~0.50 at 90%.

The log-likelihood is summed over strata, one per enzyme, so each contributes
its own `k` and `b`. Maximisation is over a single scalar `a`.

### 2.2 Why counts must come from inside chains

Restricting the counts to chained regions excludes the accessory genome from
the denominator by construction. ANI then measures divergence only, and AF
separately measures shared content. This is the structural fix for §1.2.

### 2.3 Built-in consistency check

`ani_from_loss` (loss rate only) and `ani_from_hist` (histogram only,
renormalised by `P(found)`) are independent estimators of the same quantity.
A gap larger than ~5 standard errors means the model assumptions are violated —
repeats, contamination, or a mis-built chain — and the row is flagged
`INCONSISTENT`.

The check is gated on expected retention ≥ 0.20. Below that the surviving
histogram is only the truncated tail and stops being an independent estimator,
so comparing against it produces false alarms while the joint fit is already
carried almost entirely by the loss rate.

## 3. Pipeline (`src/core/chain_ani.rs`)

1. **Anchors.** Reference tags are indexed by *strand-canonical* packed
   sequence. Sequences occurring more than `max_occurrence` (default 5) times
   are dropped: those are repeats and paralogs, and keeping them inflates the
   shared count and drags ANI down.

   Tolerant seeding uses the **pigeonhole principle** rather than a
   whole-genome scan: split each tag into `tol + 1` parts, and any pair within
   `tol` mismatches must share at least one part exactly. This is what keeps
   the method alive below ~93% ANI — a 32 bp tag matches exactly only 3.4% of
   the time at 90% ANI, too few anchors to chain, while a 2-mismatch budget
   recovers an order of magnitude more. Both orientations are indexed so
   inverted segments seed as well.

2. **Chaining.** Anchors are grouped by `(query contig, reference contig,
   orientation)` and chained by gap-penalised collinear DP. Grouping by contig
   matters: an inter-contig "gap" is the distance between two unlinked
   sequences, so letting a chain cross a contig boundary turns noise into
   apparent synteny. `max_gap` defaults to 50 kb because tags sit 0.3–2 kb
   apart depending on the panel, and a minimap2-style few-kb default shreds
   normal syntenic regions.

3. **Local fill.** Inside each chain, query→reference coordinates are
   interpolated from the chain's own anchors, and tolerant matching is done
   only within `local_window` bp of the predicted position. Seed-and-extend:
   O(1) work per gap instead of a global O(n²) scan, and — more importantly —
   it cannot invent a match between positionally unrelated tags.

4. **Estimation.** Per-enzyme histograms and miss counts go to
   `src/core/mle.rs`.

Chains are processed largest-first and each query tag is counted at most once,
so overlapping spans cannot double-count into the likelihood.

The path uses **tags only** — it never needs the raw contig sequences, so it
remains applicable to real 2bRAD sequencing data, not just assemblies.

## 4. Validation

Ground truth is exact by construction: a counted number of substitutions is
applied to a reference genome, so true ANI = `1 - n_subs / length`. Harness is
in `prototype/` (~90 MB of generated FASTA, deliberately small — no GTDB
needed).

The reference is pinned to a public accession — *E. coli* K-12 MG1655,
ENA `U00096.3`, 4,641,652 bp — so everyone simulates from byte-identical input
and the MAE below can be compared directly rather than approximately.

```bash
cd prototype
bash fetch_reference.sh mg1655.fasta
python3 simulate.py mg1655.fasta sim
python3 simulate_accessory.py mg1655.fasta simacc 0.95
../target/release/syn2bani ani sim/q_*.fasta sim/ref.fasta --verbose -p
../target/release/syn2bani ani simacc/acc*.fasta simacc/ref.fasta --verbose -p
```

| 92.000 | 92.156 | +0.156 | 0.997 |
| 94.000 | 94.009 | +0.009 | 0.999 |
| 95.000 | 94.996 | −0.004 | 0.998 |
| 96.000 | 96.046 | +0.046 | 0.999 |

**MAE 0.053%**, no training data, no calibration model, no empirical offset.
All 12 rows flagged `ok`. 12 pairs in a few seconds.

### 4.2 Accessory confound (6 genomes, true ANI fixed at 95.000, accessory 0 → 50%)

| accessory | estimate | error | AF | chains |
|---|---|---|---|---|
| 0%  | 95.044 | +0.044 | 1.000 | 1 |
| 10% | 95.106 | +0.106 | 0.896 | 6 |
| 20% | 95.074 | +0.074 | 0.796 | 6 |
| 30% | 95.071 | +0.071 | 0.698 | 6 |
| 40% | 95.250 | +0.250 | 0.597 | 6 |
| 50% | 95.140 | +0.140 | 0.496 | 6 |

**MAE 0.114%.** The estimate is flat — the residual is scatter plus a small
uniform ~+0.1 bias, with no monotonic trend against accessory fraction — while
AF tracks `1 - F` to within 0.004. The two signals are decoupled. For
comparison, genome-wide containment on the same construction drifts
95.18 → 93.27, and that drift is what GBRT was implicitly learning to undo
through `af_q`.

### 4.3 Not yet validated

- **No indels.** The sweep used substitutions plus one 400 kb inversion.
  `simulate.py` supports `indel_rate` but it was run at 0, so gap arithmetic is
  untested.
- **Accessory is simulated by shuffling** — preserves base composition and
  destroys homology, but real accessory genes differ in GC and may carry
  partial paralogy.
- **Single organism** (*E. coli* K-12 MG1655). GC content and repeat structure
  vary; high-GC and low-GC species are untested.
- **No real genome pairs.** Not yet compared against FastANI or skani on the
  15 mid-ANI pairs. That is the next step on the HPC.
- Below ~85% ANI expected retention falls under 0.20, so the consistency
  cross-check disables itself; the joint fit still works but loses that QC
  layer.

## 5. Baseline defects this path avoids

Found while reviewing HEAD `5148d88`. Listed for the record; the `dist` path
still contains them.

| Location | Defect |
|---|---|
| `ani_calculator.rs::gbrt_debias_ani` | Fabricates `shared` and `containment` from `raw_ani` (`shared = raw_ani × total.min()`). Since `raw_ani ≈ 0.95` always, `containment` is effectively constant and carries no information. The real shared count is available and unused. |
| `tag_matcher.rs` near-match fallback | Scans **all** reference tags for the global best Hamming match with no positional constraint — O(n²), and it pairs positionally unrelated tags. |
| `synteny_builder.rs::sparse_chain` | Reconstructs a chain path, then keeps only its endpoints and passes the whole contiguous `indices[start..=end]` slice to `create_block`, re-admitting the non-collinear anchors the DP just rejected. Every leftover anchor is also emitted as a singleton block. |
| `synteny_builder.rs::sparse_chain` | No `max_gap`, only `gap_diff ≤ INDEL_TOL`, so one chain can span the whole genome — "chain-restricted" then means genome-wide. Combined with the above, this is the likely cause of `chained_kmer_ani` scoring Pearson r = −0.1066: a systematic bias preserves correlation, so r ≈ 0 indicates the intervals themselves were wrong. |
| `tag_extractor.rs` | Tags were never canonicalised, so tags in inverted segments and on reverse-oriented draft contigs (roughly half of any draft assembly) could not match at all. Fixed by `canonical_packed`. |
| v7 `TagSet.sequences` | Carrying raw contig sequences to compute `chained_kmer_ani` makes the method require assemblies, losing applicability to real 2bRAD reads. |

## 6. CLI

```
syn2bani ani <QUERY...> <REFERENCE...> [OPTIONS]

  -e, --enzymes <LIST>            default: BcgI,AlfI,CspCI,AloI,FalI
      --mismatch-tolerance <N>    default: 2   (0 = exact match only)
      --min-chain-anchors <N>     default: 4
      --max-gap <BP>              default: 50000
      --verbose                   also report both partial estimators,
                                  anchor/chain counts and the consistency flag
  -p, --parallel / -t, --threads <N>
  -o, --output <FILE>
```

Columns: `query reference ani af_query af_reference std_err`, plus with
`--verbose`: `ani_from_loss ani_from_hist n_anchors n_chains n_tags flag`.

On real data, the `--verbose` columns localise any problem: `n_anchors` and
`n_chains` show whether chaining succeeded, and the two partial estimators plus
`flag` show whether the model fits the observations.
